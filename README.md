Architecture

I built a web application that uses multiple approaches for the frontend. This includes traditional HTML, client-side JavaScript, and a modern single-page application using Angular. Each approach had a specific role in the overall design. The HTML pages were used at the beginning to quickly test server-rendered views and verify how the application would work. This included checking the routing, templating, and data flow. Client-side JavaScript was added to make the application more interactive and to update the pages dynamically without needing to reload the entire page. The Angular single-page application was the final version of the frontend, and it provided a fast and responsive user experience for both customers and administrators. It was designed to be component-driven, making it easier to manage and update. On the backend, the application used a NoSQL database called MongoDB. MongoDB was chosen because it stores data in a flexible format that is similar to JavaScript, which is used on both the client and server. This made it easier to change the data model as the project grew and allowed the application to scale more easily. Unlike traditional relational databases, MongoDB does not have rigid schema constraints, which made it a better choice for this project. Overall, using multiple frontend approaches and a flexible backend database allowed the application to be more scalable and easier to maintain. This design also enabled the application to provide a better user experience and to be more adaptable to changing requirements.

Functionality

I used JSON, which is a simple way to organize and send data. It's not a programming language like JavaScript, but rather a way to structure information so it can be easily shared. One of the best things about JSON is that it can be easily sent over the internet, making it perfect for APIs. In this project, I used JSON to send data from the backend, which was built with Express, to the frontend, which was an Angular SPA. This made it easy to share data between the two, and it all worked really smoothly. As we were building the project, we also made sure to clean up our code and make it more efficient. For example, we took repeated code that was used in the user interface and turned it into reusable components. This made it easier to update the interface and reduced errors. We also did something similar with the backend code, by using shared middleware for things like validation and authentication. This made the code more modular and easier to work with. By doing this, we were able to make the application more efficient, reduce bugs, and make it easier to add new features in the future. Overall, using JSON and refactoring our code were key to making our project a success. Some of the benefits of using JSON include: * Easy to send over the internet * Simple to structure and organize data * Perfect for APIs * Made it easy to share data between frontend and backend And some of the benefits of refactoring our code include: * Reduced duplication of code * Made the interface easier to update * Improved efficiency * Reduced bugs * Made the application easier to extend

Testing

Creating a full stack application involves testing various API requests, such as GET, POST, PUT, and DELETE endpoints, to ensure they work correctly. Each endpoint must be validated to confirm proper request handling, accurate data retrieval, and correct error responses. When authentication is added, it introduces more testing challenges, as protected routes require valid JSON Web Tokens (JWTs) and proper session handling. I discovered that middleware plays a crucial role in enforcing security by verifying tokens before granting access to administrative features. By understanding how methods, endpoints, and security layers interact, I was able to ensure that both the customer-facing and admin-facing parts of the application functioned as expected under different conditions. This process helped me identify potential issues and improve the overall performance and security of the application.
